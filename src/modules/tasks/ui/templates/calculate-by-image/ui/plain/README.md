# calculateByImage — счёт предметами

Ребёнок нажимает на предметы в ряду, и они попадают в зону: корзину, клетку,
рамку. Нажатие на предмет в зоне возвращает его в ряд. Механика взята из
условий (а не придумана): «Нажимая на нужные фигуры ниже, составьте в пустые
ячейки модель заданного числа», `Task_3_1_4_1`. Канон вида — старый экран,
App › Trainer › «Тенге. Монета и бумажные» (`18938:330730`).

Каталог форм и вес механики — `qalan-docs/trainer/new-task-types.md` в
qalan-assets.

## Два варианта

| id                          | `description.type`         | Ответ                                                      |
| --------------------------- | -------------------------- | ---------------------------------------------------------- |
| `calculateByImage.plain`    | `calculateByImage`         | содержимое зоны — список `id`                              |
| `calculateByImage.withCell` | `calculateByImageWithCell` | число в поле; предметы — опора для счёта, на бэк не уходят |

## Ответ `plain`

В сторе — JSON-массив сырых `id`: `id` бывает строкой, числом или объектом
перевода (единицы «мм», «мг» в 3 классе), и бэк сверяет их как пришли.
**На бэк уходит объектом `{ list: [{ image: "", id }] }`** — так же, как
отправляет старый экран (замер на test.qalan.kz, 05.10). Строковые формы бэк
отклоняет — проверено боевым сабмитом (`trainer-rebuild-context.md`, «Ответ не
всегда строка»). Пустая зона — пустая строка, «Проверить» заблокирована.

Повторы значимы: «Дайте Шарику 15 булочек» — это пятнадцать одинаковых `id`.
`sortable?: false` в эталоне значит, что важен порядок (ответ Абдуали, #7); в
зоне предметы стоят в порядке нажатий.

Предметы, лежащие в зоне с самого начала (`items`), входят в ответ.

## Что из payload намеренно не читается

`topPosition`, `leftPosition`, `isFromLeft`, `isFromTop`, `nextItemStartAfter`
и прочие абсолютные координаты рассчитаны на экран старого тренажёра шириной
600px. На колонке 343px они выталкивают предметы за зону, поэтому предметы
ложатся сеткой. `backgroundImage` в виде `<div style="border: 1px solid
black">` — это рамка старой зоны, её рисуем токенами; картинка (`<svg>`
корзины, поляны, весов) остаётся подложкой зоны.

## Данные

`./data/tasks.json` — только целые payload: в `variants.json` длинные SVG
обрезаны (`…[+N chars]`), на них картинки ломаются. `_expected` и `_solution` —
эталон и решение бэка для ревью, шаблон их не видит.
