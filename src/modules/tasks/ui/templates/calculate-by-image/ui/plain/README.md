# calculateByImage — счёт по картинке

Ребёнок нажимает на предметы в ряду, и они попадают в зону: корзину, клетку,
рамку. Свой предмет в зоне возвращается нажатием на него. Предметы, которые
лежали в зоне с начала (`items`), закреплены: они входят в ответ, но не
убираются. Механика взята со старого экрана (`reactjs_client`,
`TaskDescriptionAndAnswerInput.jsx`), спека —
`qalan-docs/trainer/specs/count-by-image.md` в qalan-assets.

Шаблон пока **не подключён** в `available-tasks`: его включают после «да»
Алишера по виду.

## Два варианта

| id                          | `description.type`         | Ответ                                                      |
| --------------------------- | -------------------------- | ---------------------------------------------------------- |
| `calculateByImage.plain`    | `calculateByImage`         | содержимое зоны — список `id`                              |
| `calculateByImage.withCell` | `calculateByImageWithCell` | число в поле; предметы — опора для счёта, на бэк не уходят |

## Ответ `plain`

В сторе — JSON-массив индексов каталога, закреплённые предметы входят. На бэк
уходит `{ list: [{ image: "", id }] }`, как у старого экрана; перевод делает
`toWireAnswer` в `use-check-answer`. `id` бывает строкой, числом или объектом
перевода. Пустая зона — пустая строка, «Проверить» заблокирована.

Правило бэка (`CalculateByImageTaskAnswer.correct?`) перенесено в
`lib/check-calculate-by-image.ts` и проверяет истории:

- повторы значимы: «Дайте Шарику 15 булочек» — пятнадцать одинаковых `id`;
- `sortable?: false` — важен порядок нажатий;
- эталон-список списков — подходит любой вариант;
- `id` вида `coin10` — сравниваются суммы, а не монеты.

## Режимы `withCell`

`lib/with-cell-rules.ts` выбирает режим по payload, как старый экран:

- `count` — `withoutRemoveItem` или `itemsMaxQuantity: 0` («…если не
  добавлять»): поле сразу, предметы не трогаются;
- `transform` — в зоне `constItem`: нажатие в ряду превращает предмет
  («морковка кролику»);
- `remove` — ряда нет или нужно меньше, чем лежит: нажатие убирает;
- `add` — остальное: кладём из ряда.

Поле с вопросом появляется после действия (`withInputBefore`, все нажатия,
`itemsCorrectQuantity`) и больше не прячется.

## Раскладка

`maxItemsPerRow` задаёт размер предмета: ширина зоны делится на число в ряду,
но не меньше 44px и не больше 88px. `isFromTop/Left/Right` с позициями в
процентах ставят предметы на картинку зоны; пиксельные координаты старого
экрана шириной 600px не читаются. `isNotLegoTask: false` — предметы встык,
`vertical` — столбиком снизу вверх, `seperator` — через запятую.

Картинки держат пропорции своих SVG (`height` с поправкой на `viewBox`):
самая высокая занимает клетку, остальные — свою долю, но не меньше 0,3.
Предметы, которые не помещаются на картинке зоны, ложатся под неё.

## Данные

`./data/tasks.json` — целые payload реальных генераторов. В `variants.json`
длинные SVG обрезаны (`…[+N chars]`), их восстановили из модулей картинок
бэка по началу строки и точной длине. `_expected` и `_solution` — эталон и
решение бэка для ревью, шаблон их не видит.

Покрытие по всем примерам обхода считает
`npx tsx --tsconfig tsconfig.app.json scripts/audit-calculate-by-image.ts <variants.json> <coverage.json>`.
Проверку самим бэком — `scripts/calculate-by-image-backend-jobs.ts`: из задач,
построенных генераторами монолита локально, собирает ответы окна для
`TaskChecker` (`check.exs` локального бэка). Итог 26.11: `plain` принят у 558
генераторов 0–4 классов из 596, `withCell` — у 67 из 67.
